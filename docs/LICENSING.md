# PulseShield: лицензирование и `/v1/activate`

Документ описывает контракт клиента с сервером активации и сценарий с Telegram-ботом. Реализация бота и бэкенда живёт **вне** этого репозитория.

## Переменные окружения (клиент)

- `PULSESHIELD_LICENSE_API` — необязательный базовый URL API; переопределяет поле `licenseApiBase` в локальном конфиге.

## Запрос активации

**Метод:** `POST`  
**Путь:** `{baseURL}/v1/activate`  
**Заголовок:** `Content-Type: application/json`

**Тело:**

```json
{
  "code": "string",
  "hwid_hash": "string",
  "app_version": "string"
}
```

- `code` — одноразовый или подписочный код, выданный ботом после оплаты.
- `hwid_hash` — SHA-256 (hex) стабильного идентификатора устройства на Windows (см. пакет `pulseshield/app/licensing`).
- `app_version` — строка версии приложения.

## Успешный ответ

**HTTP:** `200 OK`  
**JSON:**

```json
{
  "tier": "premium",
  "valid_until_unix": 1735689600,
  "token": "opaque-string"
}
```

- `tier` — уровень подписки (`free`, `premium`, `supporter` и т.д.; клиент сохраняет как есть).
- `valid_until_unix` — Unix-время окончания; `0` можно трактовать как «без срока» (клиент: см. `AppConfig.LicenseActive()`).
- `token` — опциональный непрозрачный токен для будущих проверок.

## Ошибки

При ошибке возможны:

- не-HTTP 200 и/или поле `"error"` в JSON с понятным текстом для пользователя.

Рекомендуемые коды для привязки «один ключ — одно железо»:

- **`409 Conflict`** — код уже активирован на другом `hwid_hash`.

Клиент показывает текст ошибки из `error` или статус строки.

## Сценарий с Telegram

1. Пользователь оплачивает в боте; бот генерирует **код** (одноразовый или подписка с лимитом активаций).
2. Пользователь вводит код в PulseShield («Поддержка» → активировать).
3. Клиент шлёт `POST /v1/activate` с хешем устройства.
4. Сервер при **первом** успешном ответе фиксирует `hwid_hash` для этой подписки/кода; повтор с другим `hwid_hash` → `409`.
5. Ответ сохраняется в локальном конфиге (`LicenseTier`, `LicenseExpiresUnix`, `LicenseToken`).

Локальный JSON конфиг можно редактировать вручную; **доверенным** считается ответ сервера при активации. Для платного продукта со временем понадится онлайн-проверка по `token` — контракт может быть расширен без смены пути активации.

## Маркировка Premium узлов

Авторские узлы, требующие подписки, задаются маркерами подстрок в `PremiumServerNameSubstrings` (имя или хост сервера, без учёта регистра). Список настраивается в UI или в конфиге.
